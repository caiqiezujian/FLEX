# 旧格式数据准备：保留旧数据入口，使用最新 SFT 提示词

完整的环境、数据准备、训练与 TensorBoard 1～9 步见 [旧格式数据完整运行指南](GSPO_v4_旧格式数据_完整运行指南.md)。本文保留接口和继承来源说明。

更新日期：2026-11-02。

新增独立入口 `01_prepare_legacy.sh` 和 `prepare_legacy_data.py`，用于原有的
`lang / key / en.txt / zh.txt` 数据及 `key.wav` 音频目录。现有
`01_prepare.sh`、`prepare_data.py` 继续支持新格式 `audio / srcs / chooses`，也保留通用的 `auto / legacy / segments` 模式。

## 继承来源

已核对 GitHub `main` 在提交 `076008b3bb1ebe69b73cb5c75abd99307fdf82cb` 中的
[历史 prepare_data.py](https://github.com/caiqiezujian/FLEX/blob/076008b3bb1ebe69b73cb5c75abd99307fdf82cb/FLEX-GSPO/prepare_data.py)。
独立入口继承其旧字段和参数接口，并明确选择 `input_format="legacy"`；为了不误用旧服务器目录，
`--input-jsonl`、`--audio-dir`、`--output-dir` 需要显式提供。

两个入口共用当前 `flex_gspo.prepare.prepare_dataset`：WAV 头检查、并发探测、去重、错误报告、进度、
虚拟音频分块和输出保护沿用同一个实现。没有复制一份会逐渐失去更新的旧处理核心。

## 原始数据与音频

JSONL 一行一个对象：

```json
{"lang":"en","key":"sample_001","en":{"txt":"The meeting starts at nine."},"zh":{"txt":"会议九点开始。"}}
```

对应音频放在指定目录下：

```text
data_001/
└── sample_001.wav
```

- `key` 为不含路径和 `.wav` 扩展名的文件名主体；使用 `<audio-dir>/<key>.wav` 定位。
- `lang` 必须是 `en`，`en.txt` 与 `zh.txt` 必须是非空字符串。
- 即使旧行额外含有 `audio`、`srcs` 或 `chooses`，这个独立入口仍明确使用旧字段，不自动切换格式。
- 只有 `audio/srcs/chooses` 的新数据请继续用 `01_prepare.sh --input-format segments`。
- 英文原文和中文参考仅作为评分元数据，不放进模型输入消息中。

## 提示词

通过当前处理核心引用 `flex_gspo/prompts.py` 的 `SYSTEM_PROMPT`，与当前 SFT 中文目标模板一致：

> DIRECT与FLEX按策略区分，不按句子是否完整区分。
>
> 按语义使用标点，不随音频块机械加句号，不用省略号占位。

旧入口不会带回历史长提示词，也没有单独维护一份提示词副本。
`--system-prompt-file` 仅用于检查用户提供的内容是否与当前提示词相同，不允许借此替换成旧模板。
训练需要使用与当前模板匹配的 SFT 模型；读取旧格式数据不等于恢复旧实验的提示词、权重或奖励配置。

## 准备命令

在训练 Docker 内运行。下面的原始 JSONL 和 WAV 目录是示例路径，替换为实际旧数据地址；
输出必须使用新目录，已完成的 prepared 数据不会被覆盖。

```bash
cd /data/yb/Code/FLEX/FLEX-GSPO

source /data/yb/vens/flex-gspo-online/bin/activate

bash 01_prepare_legacy.sh \
  --input-jsonl /data/yb/Code/FLEX/datasets/1019/en2zh_train_gspo_1.jsonl \
  --audio-dir /data/yb/Code/FLEX/datasets/data_001 \
  --output-dir /data/yb/Code/FLEX/datasets/gspo_prepared_legacy_current_prompt \
  --chunk-seconds 1 \
  --workers 16 \
  --progress-seconds 5 \
  --skip-invalid
```

也可以使用 `python3 prepare_legacy_data.py`，其余参数相同；不需要额外传 `--input-format`。
`--skip-invalid` 允许跳过无效行并生成有效数据，错误会写入报告，不删除原始文本或音频。
默认时长上限 40 秒，超过的样本进入错误报告；需要调整时同时核对训练的上下文和轮数预算。

## 输出与训练衔接

```text
gspo_prepared_legacy_current_prompt/
├── train.jsonl
├── prepare_report.json
├── rejected.jsonl
└── duplicates.jsonl
```

检查 `prepare_report.json`：`manifest_published` 应为 `true`，`input_format` 为 `legacy`，
`accepted_by_format.legacy` 为实际写入的样本数。报告还记录当前提示词的 `system_prompt_sha256`。

生成的训练行仍是 `messages / audios / flex_task`。音频只生成虚拟时间切片引用，原始 WAV 不复制、
不重切，也不预先调用 SFT 模型生成八条轨迹。后续在线 GSPO 在训练中采样 G8。

继续使用现有训练命令，只把其中的数据路径替换为：

```text
/data/yb/Code/FLEX/datasets/gspo_prepared_legacy_current_prompt/train.jsonl
```

旧格式、新格式可以分别准备、分别训练，均使用当前共享提示词。该入口不更改 COMET22 v4 奖励、
模型配置、训练容量或已经开始的训练进程。

已有 prepared 文件若内嵌旧提示词，需要从原始 JSONL 重新生成到新目录；不要只替换消息文字而忽略
数据路径和音频元数据。已经由当前提示词生成、路径有效的 prepared 文件可复用，不必每次训练重新处理。
