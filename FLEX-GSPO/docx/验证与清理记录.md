# FLEX-GSPO 当前组件与验证记录

更新日期：2026-10-21。

本文只说明当前使用的 QALCO 流程、验证边界与发布范围。完整方法见 [强化学习方案详解](QALCO强化学习方案详解.md)，服务器命令见 [根目录 README](../README.md)。

## 1. 当前工程范围

唯一运行流程：

```text
外部数据工程产生任务与固定 G8 候选
                ↓
04_score.sh：评分与奖励校准
                ↓
05_train.sh：当前模型 fresh rollout → 评分 → GSPO 更新
                ↓
06_export.sh：合并导出 → 同传推理验收
```

- `FLEX-GSPO-Data` 负责数据准备及固定候选采样；本目录直接接入其产物。
- `train.py` 提供训练与预检，不提供固定候选集的独立采样入口。
- `reward.provider="qalco"` 是唯一奖励入口；质量来自独立 MetricX 文本服务。
- 本目录保留实际需要的任务校验、轨迹接入、评分接口、Q / L / C / R、GSPO、恢复、导出和测试。
- `docx/` 按指定目录名保留，文档格式为 Markdown；数学公式使用 `$$` / `$` 分隔符。

## 2. 有效组件

| 组件 | 当前职责 |
|---|---|
| `04_score.sh` / `score_candidates.py` | 校验完整候选组、调用质量服务、计算轨迹奖励与统计 |
| `05_train.sh` / `train.py` | 自包含训练启动、参数覆盖和预检；Shell 默认 `python3` |
| `06_export.sh` / `export_adapter.py` | 将训练得到的 LoRA 合并回匹配的 SFT 基座 |
| `flex_gspo/data.py` / `artifacts.py` | 任务字段、时序、转录来源和采样运行身份校验 |
| `flex_gspo/protocol.py` / `backend.py` | 原始增量输出协议、因果音频访问、模型采样与概率 |
| `flex_gspo/metricx_service.py` / `metricx.py` | 外部文本评分接入点、参数和返回值校验 |
| `check_metricx_service.py` | 使用合成文本检查 QE / reference 真实接口，不加载模型或音频 |
| `flex_gspo/qalco.py` / `rewards.py` | QALCO 奖励与统一错误处理 |
| `flex_gspo/trainer.py` / `runtime.py` | 完整轨迹 GSPO、四卡同步、运行记录和严格恢复 |
| `tests/` | 数据契约、奖励、训练数学和工程行为的回归验证 |

```bash

bash -n 06_export.sh
python3 score_candidates.py --help
python3 train.py --help
python3 export_adapter.py --help
python3 check_metricx_service.py --help
```

2026-10-21 本轮服务接入后，根代理在隔离 CPU 测试环境实际执行完整测试集：**166 项全部通过，0 项跳过，耗时 3.509 秒**。新增测试包括真实本地回环 HTTP 端到端检查：在 `127.0.0.1` 临时端口启动测试服务，验证环境代理绕过、QE / reference 实际 POST 与响应解析；其他服务响应测试使用模拟对象。

本轮未访问实际部署的内网评分服务，未运行真实 MetricX 权重，也未执行 GPU 或四张 A800 训练。本地 HTTP 测试通过不等于用户内网、真实评分质量或训练流程已验收。

此次服务对接不修改奖励公式、GSPO 目标、教学数值或 `$$` / `$` 数学分隔符。

测试重点包括：

- 完整候选组、重复组、运行身份、损坏时序与 mock 数据的校验。
- MetricX 输入字段、批量顺序、原始错误分范围和异常处理。
- 服务配置、网络或响应异常时明确报错，不生成假奖励。
- QE 不传参考；质量评分不传音频、动作标签或时序。
- Q、LAAL、超长成本、分层奖励及方法文档的教学数值。
- WAIT / FLEX / DIRECT 协议，以及相同文字和时间下 FLEX/DIRECT 标签不改变奖励。
- 完整轨迹分解梯度与整体梯度、微型 CPU 策略优化器更新和概率一致性。
- checkpoint 文件完整性、优化器恢复与运行身份匹配。
- LAAL 的 EOF 截止非单调反例，明确记录指标限制。

测试中的固定质量分数只是数值测试输入，不代表真实 MetricX 评分。CPU 测试通过也不等于真实 Omni 或四卡 GPU 验收完成。

## 4. 尚需服务器验收的事项

- 用户 SFT checkpoint 加载、真实音频生成与特殊 token 对齐。
- 四张 A800 的显存峰值、NCCL 通信、吞吐和长轨迹开销。
- 真实 Qwen3-Omni 生成与重算的概率一致性。
- MetricX 在训练服务器上的内网连通性、真实响应和实际评分区分能力；远端权重版本须由服务侧部署记录保证。
- 导出模型接回现有离线 / 流式推理系统。
- 训练收敛、质量、自然度和时延的独立评估。

当前方法没有实现逐次 WAIT 的因果价值估计或前缀语义支持审计，不能把完整轨迹奖励解释为这些能力。

## 5. 当前接入状态

客户端已实现用户提供的批量文本评分协议：

```text
service_url = ""  # 使用前填写实际服务基础地址
service_id = ""   # 使用前填写固定部署标签
mode = "qe"
calibration_acknowledged = false
```

QE 调用 `/metricx24/qe`，发送 `srcs` / `mts`；reference 调用 `/metricx24`，额外发送 `refs`。两者解析 `scores` 数组。客户端关闭环境代理与重定向，连接/读取超时 10/180 秒，连接错误、超时及 HTTP 429/502/503/504 最多两次尝试、间隔 1 秒；校验数量和有限的 `[0,25]` 数值，失败不使用默认分。

任务中的源转录来自 `en.txt`，机器参考来自 `zh.txt`；待评 `mts` 是模型实际生成的完整译文。默认 QE 不发送机器参考，但训练端仍用参考做长度预算和 LAAL。切换带参考模式需要重新校准。

服务没有返回版本和样本 ID，`service_id` 仅为本地声明标签，不能自动核实远端 checkpoint 或同长度响应的语义配对。必须由服务端保证模型版本固定及数组顺序，客户端检查不替代人工抽查。

在训练服务器执行 `python3 check_metricx_service.py --mode both` 可用合成文本检查真实连通性，无需模型和音频。配置结构预检中的 `quality_service_ready` 不是网络健康检查。当前尚未完成用户内网实际请求、四卡训练或奖励有效性验收；需完成这些检查和校准后再正式训练。

## 6. 公开发布范围

本目录只发布源码、示例配置、测试和方法文档。实际服务地址、个人服务器路径、本地备份位置、模型权重、训练音频、已采样轨迹和运行日志不随代码发布。`FLEX-GSPO-Data` 是独立的数据准备工程，不包含在本次发布目录中。

训练恢复要求代码、配置及运行身份匹配；不能使用变更后的代码强行接续身份不一致的 checkpoint。
