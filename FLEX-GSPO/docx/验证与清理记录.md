本次仅重建 `FLEX-GSPO/` 内的强化学习实现。原作者修改前已保留完整本地备份，备份不随公开仓库发布。

删除旧自写训练器及固定离线轨迹主流程入口：`04_score.sh`、`05_train.sh`、`06_export.sh`、`train.py`、`score_candidates.py`、`export_adapter.py`、`export_completed.py`，以及不再使用的 backend/trainer/runtime/artifacts/snapshot 模块和对应旧测试。原作者可从本地备份取回；公开仓库的旧版本可从 Git 历史查看。

当前入口只有：准备 `01_prepare.sh`、在线训练 `02_train.sh`，以及显式环境辅助 `00_install_framework.sh`。三个 shell 脚本均使用 python3。

## 已进行的验证

- 原始 JSONL、按 key 去重、缺失音频/损坏文本处理、严格模式、进度和输出覆盖保护。
- 真实 WAV 区间读取、边界补零、16k/48k 音频局部重采样、源文件变化检测。
- SFT 原始 system prompt 完全一致；转录/参考不进入模型消息。
- WAIT、FLEX、DIRECT 多轮轨迹；非法输出保留为负例，不修复或重采样掩盖错误。
- 原始生成 token、log-probability、loss mask 和全部已听音频字段的传递。
- 完整译文评分、重复译文质量调用去重、HTTP 错误处理和无效轨迹区分。
- 同一译文更晚释放不会因 EOF 截断变得更低延迟；全 WAIT 和最后合法 WAIT 的区别。
- 启动参数、数据清单、checkpoint token、恢复身份等预检。
- 真实 WAV → prepare → 多轮环境 → 本地 HTTP MetricX 替身 → QALCO 的 CPU 贯通测试。

2026-10-21 原项目本地完整测试结果：**161 项全部通过，没有跳过**。公开发布副本复测 161 项，160 项通过、1 项因原始 SFT 脚本未随仓库发布而跳过（SFT 提示词原文件逐字核对）；其余源码合约测试已提供审查源码并执行。三个 shell 入口分别通过 `bash -n` 语法检查。测试日志中故意构造的损坏输入、HTTP 失败等报错是负向用例，不是实际训练发生故障。

部分测试直接提取并运行官方源码中的多轮调度和样本合并方法，用轻量替身避免加载 CUDA。审查源码提交：`modelscope/ms-swift@f15bb91439d756d4a366b51956d72d1f088b7af6`。这种测试验证接口契约，不是实际模型前向。

## 四卡多轮退出同步修复


用户随后提供了四个进程的真实堆栈：两个停在 `_colocate_rollout` 的 vLLM 四卡汇总，另两个已经进入 `_log_completions_from_samples`。结合固定提交源码，定位为多轮完成判定采用 Megatron 两进程组，而实际推理需要四进程组；候选结束时间不同导致通信阶段分叉。用户日志也显示 MetricX 连通性探测通过、checkpoint 加载并进入 Epoch 0，但尚无成功完成优化步骤的证据。

新增 `flex_gspo/rollout_sync.py` 并通过 `swift_plugin.py` 自动安装兼容包装。只将 FLEX-colocate 的完成判定改为实际 `trainer.vllm_tp_group`，保留原上游多轮循环与空请求通信；不改变 Megatron 数据分配组、生成 token、loss mask、logprob 或奖励数值。增加源码契约预检、逐轮阶段日志和评分开始/结束日志。未重装框架、未改写上游文件，未修改音频或训练数据。

本轮最终验证：**174 项 CPU 测试全部通过，0 跳过**。其中新增 5 项真实上游循环的四 rank 模拟、7 项实际 `_generate_completions` 方法的包装接线测试、1 项启动参数回归。原分组反例可复现参与者缺失；修复后不等长、空请求、无效输出早停都能统一退出；TP1、非 FLEX、server 透传、重复安装和异常上下文恢复也通过。

以上为原项目工作目录的结果。公开发布副本另行复测 **174 项：173 项通过，1 项跳过**；跳过原因是原始 SFT 脚本不随公开仓库发布，无法逐字比对该原文件。通过 `FLEX_SWIFT_SOURCE` 提供固定上游源码后，本次新增的 12 项同步/安装测试和原上游合约测试均实际执行，没有跳过。发布配置继续保留空的服务地址和实例标识，示例命令不含实际私人服务器路径。

完整 CPU suite 使用本地 Python 3.9.12 轻量依赖环境运行；这不意味着训练支持 Python 3.9，服务器训练仍要求 Python 3.10 及以上。另用 Python 3.12.14 对 33 个项目/测试 Python 文件通过 AST 语法检查，并通过 G8/B32 两步命令 dry-run。三个 shell 入口本轮再次通过 `bash -n`。本地没有执行 CUDA 模型推理、NCCL 通信、反向更新或远程 MetricX 调用。
